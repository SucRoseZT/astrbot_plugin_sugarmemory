01它是什么

给聊天机器人补三样东西：记得住（分层记忆）、有亲疏（好感度）、知道人和人的关系（关系图）。

数据全部落在本地一个 SQLite 文件里，不联网、不依赖向量库、不自带 embedding 模型。除了它自己触发的阶段总结，平时聊天不会多花你一次模型调用。

三条设计取向，理解了这三条，后面所有行为都能推出来：

  • 能算的不用模型猜。检索、打分、裁剪、去重全是字符串运算和算术，不调模型。
  • 模型的输出只是草稿。总结返回的事实、关系，落库前要过门控和指纹去重，不合格就丢。
  • 注入量可数、可关。每轮塞进 prompt 的东西有 token 预算，超了按规则砍；每个模块都有独立开关。

02三层记忆

L3 原话每条消息一行
保留天数可设
会话摘要攒够一批才做
把一长段压成几行
L2 事实从摘要里抽
带说话人和置信度

L3 事件流：用户每发一条、AI 每回一条，各落一行，带说话人、会话 ID、到期时间。默认保留 14 天，到期由清理任务删掉，设 0 就永久留着。

会话摘要：同一个会话累计满 50 条用户消息（默认值，下面几个数字同理），再等 10 秒确认这轮聊完，就把最近 60 条用户消息 + 30 条 AI 回复拼起来，调一次模型，让它输出摘要 + 事实 + 关系。摘要也写在 l3_events 里，用 session_summary 标记。

L2 事实：从摘要里抽出来的「谁 · 是什么」，例如「小明 · 女朋友 · 小红」。每条都有 speaker（谁说的）和 confidence（多确定）。

怎么防重复：指纹 = sha256(subject|predicate) 取前 32 位。同一个指纹再次写进来，旧那条标成 replaced 并把 replaced_by 指向新那条，不删也不覆盖。所以面板里能点开一条记忆看它的修订链路，知道从哪句原话开始、中间改过几次。

为什么非要分三层：原话太占地方但不能丢（要能追溯），摘要省地方但会糊（细节被模型吃掉），事实最省但会过时（关系会变）。三层各留一份，用的时候按预算取。

03记忆包：每轮现拼，从不缓存

每次你说话、在模型开口之前，插件现拼一段文字塞进 system_prompt，这段就叫记忆包。不写进对话历史，所以不会滚雪球。

四步：

  • 取候选：当前说话人的有效 L2（默认最多 12 条）+ 相关 L3 原话（默认 5 条）+ 本会话摘要
  • 打分：把你的话和每条记忆都拆成相邻两字（2-gram），重合越多分越高；分数 = 重合数 × 2 + 置信度 + 稳定性 × 0.1。纯字符串运算，不调模型
  • 裁剪：超过预算（默认 600 token）就先砍 L3 原话，还超就砍低置信的 L2，直到塞得下
  • 渲染：拼成一段带标题的结构化文本写进系统提示

作用域：默认按人隔离，只取当前说话人的事实和本会话的摘要。关掉这个开关会变成全库检索，别人聊过的东西会跑到你的对话里，面板调试时才建议关。

用 2-gram 是因为它零成本、可解释、不会有假命中到离谱的程度。代价是不懂同义：你说「对象」，它翻箱倒柜也找不到「男朋友」那条。

04人物身份（AI 与人）

一句话：一个人 = 一个 QQ + 一串称呼。好感、关系、记忆都记在「人」身上，不记在某个写法上。

为什么要多这一层：同一个人的叫法太多——昵称、外号、英文名、甚至别人打错的名字。以前这些写法直接拿来当键，于是「小红」和「徐老鸭」在库里变成两个人，好感各记一半、关系图上两个点。

  • QQ 是身份锚：私聊时从会话串里自动认出 QQ 并绑上，面板里也能手动填。绑了以后换昵称、被叫外号都还是同一个人
  • 称呼表：每个称呼指向一个人。面板能加能删；删错不影响记忆，只是以后不认这个叫法
  • 自动学：你说「A 就是 B」「A 也叫 B」「B 是 A 的外号」时当场学下来（纯正则，不调模型），并且立刻把已经裂开的两个节点合回去
  • 只在有把握时自动合：写法相同（含看不见的占位字符）、QQ 相同、你亲口说过是同一个人——这三种才自动合。读音一样但字不同（王伟 / 王薇）只在面板上标「疑似同一个人」，点一下才合
  • 好感度：每人一个分数，你每说一条消息涨一次：4 × (1 - 当前分 / 上限)，最少 +1，越接近上限越慢，永远到不了顶。分数对上「阶段表」的阈值就是阶段，名字和阈值都能改
  • 影响语气：开着这个开关时，插件按阶段名里的关键词生成一句语气提示，跟着关系快照一起注入。名字里带「恋 / 爱 / 甜 / 暧昧」就提示亲昵宠溺，带「友」就熟络轻松，认不出就退回客气拘谨

05人际关系

一句话：这张表记的是「谁认为谁是什么」，不是事实库。

每条边是「A 认为 B 是某某」。三个人各自说「小明是我男朋友」，就是三条互不覆盖的边。所以它会记下互相矛盾的说法，这是设计如此，不是 bug。人说谎、转述、开玩笑，只要是他自己讲的，都照记。

  • 证据：每条边可以挂多条原话，点开某人能看到这些原话
  • 快照注入：每轮只带当前说话人相关的边（默认 6 条），渲染成人话塞进系统提示，让 AI 知道该用什么口气
  • 工具：AI 可以调「记关系」（写）和「查关系」（读），两者都要过右边那六道闸
  • 重名归并：写之前先问「这个人是谁」——先查称呼表（徐老鸭 → 小红），认不出再看库里有没有同一个写法（只差括号备注、大小写、看不见的字符就算同一人，「张三」和「张三（群友）」合成一条）。都认不出才新建，并且立刻有身份记录，面板上就能给它绑 QQ

06群聊策略：默认完全只读

群里默认只做三件事：读记忆、答话、别的什么都不干。

  • 不写聊天记录，所以群聊内容一个字节都不入库
  • 不加好感度
  • 不计入总结条数，不会把私聊的总结节奏带偏
  • AI 不能改关系（开关默认关）
这个插件没有做群聊适配，也不打算做。真要开，会遇到三个必现问题：说话人归属错乱（A 说的话被当成 B 的）、L2 互相串台、token 被群聊白白吃掉。开了之后出现的任何记忆错乱，都不算 bug。

怎么判断在群里：三级兜底——先问适配器要群号，拿不到就看消息来源串里有没有群标记，还不行就看消息对象的类型名。因为不同适配器这三个来源不一定都给，只靠一个会把群聊当私聊处理。

群不会出现在关系图和好感度里：见到一个群就把它的群号（和群名）记进 known_groups，读的时候凡是命中群号/群名、或者带 group: 前缀的，一律当群滤掉，不画节点、不算好感。历史数据会从存下来的会话串里反推群号补登记一遍。万一有人被误判成群，把那条群记录删掉即可，人或数据本身都没动。

07推荐的配置顺序

  • 先别开注入。默认是影子模式：照常记录，AI 看不见。先跑几天，在面板里看记录得准不准
  • 觉得记得对，再开「注入记忆」。这时候 AI 才开始真的用上这些记忆
  • 只留一个记忆插件。装了别的同类插件就关掉这个的注入，否则同样的内容会注入两遍，白烧 token
  • 主人权限按需开。开了「只限主人」，就要确认你自己在管理员里，或者把自己的号填进额外授权名单，不然连你自己都会被挡
  • 总结专用模型可以挂个便宜的小模型。总结不追求质量，只追求把事记下来

01数据存在哪

一个文件：data/plugin_data/astrbot_plugin_sugarmemory/memory.db。备份就是复制这个文件，换机器带走也是它。

表存什么
l3_events事件流。原始聊天（event_type=chat）和会话摘要（session_summary）都在这里，靠类型区分
l2_facts长期事实：谁 · 什么属性 · 什么值 · 谁说的 · 置信度 · 指纹
gate_audit门控审计：每条候选事实为什么被收下或被拒
people一个人一行：规范名 + 绑定的 QQ
person_alias称呼表：每个写法指向一个人（另存读音键，只用于「疑似同一人」提示）
affinity每人一个好感度分（当前值 + 累计获得）
affinity_stages阶段表：名字 + 阈值，面板可改
social_relations有向关系边：source 认为 target 是 relation
relation_evidence关系原话证据，一条关系可以挂多条
token_usage每次模型调用的账：模块、真实还是估算、输入 / 缓存 / 输出
tool_idem幂等锁，工具写操作的指纹和时间戳
circuit熔断状态，落库所以重载插件不会清零

表是插件启动时 CREATE TABLE IF NOT EXISTS 自动建的，升级时只加列不删列，老库不会崩。

02工具调用的几道闸

写数据是唯一有破坏性的动作，所以从「AI 想写」到「真的写进去」之间排了六道闸，任何一道拒了都写不成。

闸拦什么实现
① 开关整个工具不让用发请求前把工具从工具箱里摘掉，模型根本看不见它
② 身份谁能用平台管理员，或填进「额外授权名单」的号
③ 范围路人借 AI 改别人的关系非主人只能改「含他本人」的边，碰不到两个第三人之间的
④ 原话AI 被读到的文字骗想记的两个名字至少一个要出现在你这条消息里，否则软拒并让 AI 回头问你
⑤ 幂等模型重试写好多遍指纹 + 时间窗，重复的直接当成功返回，不再落库
⑥ 熔断一直失败还一直烧钱连续失败 3 次进 600 秒冷却（都可改），冷却完放一次探测，成功即恢复

第 ④ 道是软拒绝：不报错，只回一句「这两人本轮没提到，先跟他确认」。AI 收到通常会回头追问一次，而不是把错误当成故障抛给你。

第 ④ 道拦不住「你自己转述别人的话」——那种情况下两个名字都在你的原话里，属于你说的，照记。它只解决「AI 把读到的内容当成你授权的」。

03Token 统计

每次模型调用落一行账，记模块、来源、输入 / 缓存 / 输出三段。

  • 真实值：普通对话和阶段总结拿得到模型返回的用量，标 actual
  • 估算值：记忆包、关系快照不单独发请求，只能在拼装时按字数估，标 estimate
  • 缓存命中恒为 0：框架只认 OpenAI 格式的 prompt_tokens_details.cached_tokens，而 DeepSeek 把命中数放在顶层 prompt_cache_hit_tokens，框架没读，插件拿不到

面板里能看总量、24 小时、7 天、30 天，各模块占比，以及最近的逐条调用。清空是两步确认，防止手滑。

05已知限制

  • 群聊没有说话人归属，所以只读。这不是没做完，是不打算做
  • 记忆包只按人隔离。群里 A 提到 B 的事情，存下来挂在 B 名下，不会注入给 A
  • 拿不到缓存命中数，是框架层的解析问题，插件这边补不了
  • 检索不懂同义，2-gram 只认字面重合
  • 总结是单次调用。返回的 JSON 解析失败会退避重试 3 次，三次都不行就跳过这一批，等下一批
  • 面板里没有弹窗。沙箱禁了系统的 alert / confirm，所以危险操作都是「点两次」确认

06配置到底该在哪改

有 两个入口，改的是同一个配置文件，但生效方式不一样，别弄混：

入口生效说明写在哪
本面板「设置 → 配置项」立刻，没有保存按钮每项下面都有一行白话解释
AstrBot 官方插件配置页要保存 + 重载插件，只保存不重载跑的还是旧值也是白话解释，但分组按框架的方式展开

建议一律在本面板里改，尤其是这几组：记忆、注入、总结、好感度、主人权限。原因很实际：在这里改完立刻生效，你可以马上发一句话看效果；在官方页改完要重载，重载前那段时间面板显示的是新值、插件用的还是旧值，很容易以为「改了没用」。

官方那个配置页只当兜底用：插件没启动、面板打不开、或者你把「记录聊天」关错了导致面板没数据的时候，才去那边改。

另外，官方配置页最顶上有条提示项（一项空字符串，叫「先读我」），它不参与任何逻辑，就是提醒你这件事，不用填、也不用管。
